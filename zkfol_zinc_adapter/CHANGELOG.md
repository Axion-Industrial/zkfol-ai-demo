# Changelog

## 0.5.14

- Added a practical Zinc constraint-shape report to exports, explanations, inspections, resource preflight, progress heartbeats, benchmark summaries, and Rust runner output.
- The report answers: scalar variables, constraints, declared CCS/R1CS degree, simplified witness degree, and bit-bound delta.
- Split the bit-bound explanation into public-input, private-witness, and constraint-coefficient bit lengths.
- Updated README, output guide, command reference, options reference, pipeline guide, and benchmarking docs to explain these fields and how they relate to paper-level AIR parameters.
- Added regression tests so the variables/degree/bit-bound fields remain visible in normal output and generated JSON.

## 0.5.12

- Clarified Zinc timing output after observing cases where `ZincVerifier::verify` is slower than `ZincProver::prove`.
- Added explicit timing fields: `field_setup_ms`, `field_relation_check_ms`, `zinc_prove_call_ms`, `zinc_verify_call_ms`, and `measured_iteration_ms`.
- Kept `prove_ms` and `verify_ms` as backward-compatible aliases for the Zinc library-call timings, but documented that they are not total prover/verifier system costs.
- Updated benchmark summaries, output guide, low-level command docs, and timing glossary to explain that current proof-of-concept verifier calls can be slower than prover calls on adapter-generated CCS instances.
- Added a runner timing note in human-readable output when verifier-call time exceeds prover-call time.

## 0.5.11

- Added `docs/OPTIONS_REFERENCE.md`, a complete practical option reference for the high-level `folzinc` wrapper, lower-level Python CLIs, and direct Rust runner.
- Added `folzinc options` / `folzinc option-reference` so users can print the option reference from the command line, even before activating the venv.
- Expanded argparse help text so public options no longer appear without practical explanations in `--help` output.
- Updated README and all topical documentation to point to the new option reference, with special emphasis on `--int-limbs`, strict limb forcing, progress heartbeat controls, and resource-preflight flags.
- Added documentation regression coverage so key public options must remain described in the option reference.

## 0.5.10

- Fixed the tiny-Fibonacci/oversized-limb regression: high-level commands now downshift `--int-limbs N` to the smallest safe profile by default. For example, `fib --n 3 --int-limbs 128` uses `Int<2>/RandomField<4>` unless `--strict-int-limbs` / `--force-int-limbs` is supplied.
- Added Rust runner support for `--strict-int-limbs`, `--force-int-limbs`, `--allow-oversized-limbs`, and `--version`.
- Added stale release-binary detection: if `target/release/zkfol-zinc-runner` reports an older version or no version, the wrapper does not silently use it after a package upgrade.
- Counted sampled random-field setup as its own heartbeat phase, so long prime/config generation is visible instead of being misattributed to the previous phase.
- Added regression tests for oversized limb downshifting, strict limb forcing, stale runner binary detection, and the updated progress unit accounting.

## 0.5.9

- Added an integrated regression test suite covering the bugs encountered so far: signed sparse-matrix handling, concrete Zinc dispatch, sampled-field relation checks, exact non-modular Fibonacci semantics, stale benchmark-file filtering, progress heartbeat/RSS reporting, resource preflight, JSON result collection, and CLI output expectations.
- Added `folzinc test` as the single-command entry point for tests.  The default suite is Python-only; `--cargo` adds a real Rust runner build check, and `--zinc-smoke` adds a tiny real Zinc prove/verify smoke test.
- Added optional environment-controlled Cargo/Zinc tests via `FOLZINC_RUN_CARGO_TESTS=1` and `FOLZINC_RUN_ZINC_SMOKE=1` for CI and power users.
- Updated README, command reference, benchmarking docs, root wrapper help, and changelog to explain the test suite and when to run it.

## 0.5.8

- Fixed benchmark-suite path selection: `folzinc bench fib --n 1000` now explains and runs only the `n=1000` JSON generated by that command, even if older `n=100` or `n=10000` JSON files remain in the output directory.
- The same stale-file fix applies to power benchmarks when selecting `--power-profile` or `--skip-*` options.
- Added `--clean` / `--clean-output` to `folzinc bench` to remove old generated JSON/CSV/Markdown files from the selected suite output directory before exporting.
- Added a note when stale JSON files are present but ignored, so users understand why old files remain on disk but are not part of the current run.

## 0.5.7

- Added a resource preflight estimator for Zinc proof runs. It predicts the padded Zinc dimension and the largest dense allocation that the current public Zinc proof-of-concept is likely to materialise.
- `folzinc run`, `folzinc demo --zinc`, and `folzinc bench ... --run` now refuse very large proof runs by default instead of letting the process hit an opaque allocator failure.
- Added `folzinc estimate` / `folzinc preflight` to inspect resource estimates before launching Zinc.
- Added `--max-single-allocation-gib` and `--allow-large` controls for users with larger machines or who intentionally want to override the safety gate.
- Benchmark summaries can now record resource-preflight skips without pretending a proof was run.
- Documented that `standard_power_2_32_public` is a resource stress test for the current Zinc proof-of-concept; routine power timings should use the efficient repeated-squaring profile.
- Added `--allow-large-zinc` / `--run-large` aliases for `--allow-large`.

## 0.5.6

- Updated the progress heartbeat to report approximate RSS memory for the Cargo/Zinc process tree, plus peak observed RSS, process count, and largest live processes when available.
- Updated README, command reference, output guide, and benchmarking guide so progress documentation now covers both CPU and memory reporting.
- Kept the v0.5.5 compact exact-Fibonacci benchmark profile and bold concrete-computation lines unchanged.

## 0.5.5

- Bolded the main `Concrete computation: ...` line in Python CLI output and in the Rust runner's human report when stdout is a terminal.
- Added concrete computation printouts to benchmark runs, including exact non-modular Fibonacci cases, before invoking Zinc.
- Added the compact exact-Fibonacci benchmark profile and made it the default. It keeps the same exact public Fibonacci claim but treats canonical index/pointer rows as public relation structure, reducing large Fibonacci runs from about `5n` constraints and `4n` witness variables to about `n` constraints and `n` witness variables.
- Added `--fib-profile compact|full` for users who want the older explicit four-row direct Fibonacci trace.
- Updated README/benchmark docs to explain the faster Fibonacci profile and how to select the full profile.

## 0.5.4

- Fixed a Rust runner integer-conversion bug that could let the local `CCS_Z<Int<N>>` check pass while the sampled-field Zinc relation failed during verification, especially for exact Fibonacci rows with negative linear coefficients.
- Added an explicit sampled-field relation check before each Zinc proof attempt, so future encoding/limb-width problems fail early with a clearer message instead of surfacing later as a Spartan sumcheck panic.
- Updated progress accounting to include the sampled-field relation-check phase.
- Changed zero-check rows to use the explicit public-zero coordinate on the RHS, which avoids all-empty C matrices for linear-only benchmark suites.
- Changed the direct exact-Fibonacci benchmark to positive-oriented rows `<left,z> * 1 = <right,z>`, avoiding negative coefficients in that specialised benchmark.
- Changed the direct exact-Fibonacci benchmark to encode `n` and exact `F_n` as public relation constants rather than extra Zinc public-input coordinates, while keeping the claim visible in JSON metadata and inspection output.
